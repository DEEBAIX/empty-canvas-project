# تطوير المنصة + النشر على VPS

## 1. صفحة رفع الملفات

### الدول
حالياً 18 دولة فقط في قاعدة البيانات (KW, AE, SA, QA, BH, OM, EG, JO, LB, TR, GB, DE, FR, IT, ES, NL, SE, US).
- إضافة كل دول العالم (~250 دولة، ISO-2 + الاسم بالعربي والإنجليزي + مفتاح الاتصال الدولي).
- حقل بحث داخل قائمة الدول + زر "إضافة دولة يدوياً".
- مفاتيح الاتصال تُقرأ من الجدول بدل القائمة المكتوبة داخل الكود، ليعمل تنسيق الأرقام لكل الدول.

### أنواع الملفات
الآن CSV فقط. سيتم دعم:
- `.csv` / `.txt` (فاصلة، فاصلة منقوطة، Tab، Pipe — كشف تلقائي)
- `.tsv`
- `.xlsx` / `.xls` (Excel)
- `.json` / `.jsonl`
- ملفات مضغوطة `.gz` اختيارياً

ملاحظة مهمة عن Excel: ملف XLSX بحجم جيجابايت لا يمكن قراءته في المتصفح (يجب فك ضغطه كاملاً في الذاكرة). لذلك:
- Excel مدعوم حتى ~200 ألف صف.
- الملفات الضخمة (1–4 جيجا) يجب أن تكون CSV أو TXT — وهي تُقرأ بالتدفق (streaming) بلا حد أعلى.
- إذا اخترت ملف Excel كبير، تظهر رسالة تطلب تحويله إلى CSV.

## 2. الأعمدة الديناميكية (أهم نقطة)

المشكلة الحالية: نحفظ 7 حقول فقط، وبقية الأعمدة (first name, last name, Facebook ID, gender, birthday…) تُدفن داخل `extra` ولا تظهر ولا يمكن فلترتها.

الحل:
1. **قاموس الأعمدة (Column Dictionary)** — جدول جديد يحفظ كل عمود قابلته المنصة: الاسم الأصلي، الاسم الموحّد، النوع، والمرادفات. عند رفع أي ملف نقرأ السطر الأول فقط ونطابقه مع القاموس:
   - عمود معروف (بأي صيغة: `fname`, `first name`, `الاسم الأول`) ← يُربط تلقائياً بالحقل الموحّد.
   - عمود جديد ← يُنشأ له مدخل في القاموس ويصبح معروفاً في كل الملفات القادمة.
2. **ملف Template** — عند إرسالك ملف Excel النموذجي، نقرأ السطر الأول منه ونعبّئ به القاموس كأساس. (لم يصلني الملف بعد — أرسله وسأدخله.)
3. **تخزين مرن** — الحقول الشائعة تبقى أعمدة حقيقية (سريعة للفلترة)، وكل عمود إضافي يُحفظ في `extra` مع فهرس JSONB، فيصبح قابلاً للبحث والفلترة والعرض دون تعديل الجداول.
4. **شاشة المراجعة قبل الرفع** — تعرض: العمود في ملفك ← الحقل المطابق (مع إمكانية التعديل) + معاينة 5 صفوف. الحفظ يجعل نفس التطابق تلقائياً في المرات القادمة.
5. صفحة "البيانات" تعرض الأعمدة الفعلية للمجموعة المختارة، لا 7 أعمدة ثابتة.

## 3. الملفات الضخمة (1–4 جيجا)

نعم، مدعومة — لأن الملف **لا يُرفع**: المتصفح يقرأه من قرصك على دفعات ويرسل الصفوف فقط. لكن السرعة الحالية بطيئة (2000 صف/طلب). التحسينات:
- رفع دفعات 10,000 صف + 3 طلبات متوازية (~10× أسرع).
- استئناف الرفع بعد الانقطاع من آخر صف نجح.
- عرض الوقت المتبقي والسرعة (صف/ثانية).
- مؤشر تقدير: ملف 2 جيجا ≈ 8–15 مليون صف ≈ 25–50 دقيقة.

## 4. مفاتيح API — توضيح الصلاحيات

العلاقة بين "الدول" و"المجموعات" حالياً **OR** وهذا مربك. سيصبح واضحاً بثلاثة خيارات صريحة:
- **وصول كامل** — لا قيود.
- **حسب الدول** — يرى كل مجموعات الدول المختارة (بما فيها المستقبلية).
- **حسب مجموعات محددة** — يرى تلك المجموعات فقط، ولا حاجة لاختيار دولة معها.

نعم، المفتاح الحالي يعمل فوراً في أي منصة أخرى بمجرد وضعه في الهيدر — لا خطوة إضافية.

## 5. Data Filter داخل المنصة

برنامج DATAFILTER.exe لا يمكن تشغيله داخل موقع ويب (برنامج Windows). لكن سنبني **بديلاً أقوى منه** داخل الداشبورد، لأن البيانات في قاعدة بيانات وليست ملف نصي:

- زر "فلترة" على كل مجموعة يفتح شاشة الفلترة.
- بناء شروط مركّبة على أي عمود: يساوي / يحتوي / يبدأ بـ / فارغ / غير فارغ / ضمن قائمة / نطاق تاريخ.
- **Distinct** (إزالة التكرار حسب عمود مختار) — نفس زر البرنامج.
- **Merge / Split** — دمج مجموعات، أو تقسيم النتيجة إلى مجموعات فرعية بعدد صفوف محدد.
- **Replace / Add prefix-suffix** على عمود مختار.
- عدّاد النتائج المباشر (Count).
- **حفظ الفلتر كمجموعة جديدة** داخل المنصة، أو **تصدير CSV/XLSX**.
- **حفظ الفلتر كـ View مسمّى** وربطه بمفتاح API — فتصبح المنصة الخارجية ترى النتيجة المفلترة فقط.

### كيف تقرأ المنصات الخارجية البيانات
مثال عملي: رفعت ملف الكويت، أنشأت مفتاحاً مقيّداً بالكويت. المنصة الأخرى تنادي:

```text
GET /api/public/v1/leads?country=KW&fields=phone&has_phone=true&page=1&limit=1000
Authorization: Bearer lk_live_xxx
```

- ترجع JSON فقط بالأعمدة المطلوبة (`fields=phone` = رقم الهاتف وحده).
- تدعم نفس شروط الفلترة (`filter[city]=Salmiya`, `updated_since=...`).
- لا يمكنها تجاوز حدود المفتاح إطلاقاً — الفلترة تُطبَّق في قاعدة البيانات.
- endpoint إضافي `/api/public/v1/schema` يخبر المنصة الخارجية بالأعمدة المتاحة.

## 6. النشر على VPS (Hostinger)

سأسلّمك في ملف `DEPLOY.md` داخل المشروع:

- **Script 1 — النشر الأول**: تثبيت Node 20 / PM2 / PostgreSQL 16، استنساخ الريبو بالتوكن إلى `/var/www/DATAHub`، إنشاء `.env`، `npm ci && npm run build`، تشغيل PM2، Nginx reverse-proxy على `data.tg-kw.com` بجانب مواقعك الحالية، و SSL عبر Certbot.
- **Script 2 — إعادة النشر**: أمر واحد `datahub-deploy` = `git pull && npm ci && npm run build && pm2 reload`.
- **Script 3 — Webhook تلقائي**: مستمع Node على المنفذ 8989 مع تحقق توقيع HMAC، يُدار بـ PM2، مع خطوات ربطه في GitHub.
- **Script 4 — قاعدة البيانات**: تثبيت PostgreSQL محلياً على الـ VPS، إنشاء المستخدم والقاعدة، تطبيق كل الـ migrations، و`pg_dump` من Lovable Cloud ثم `pg_restore` على الـ VPS لنقل بياناتك الحالية.
- **Script 5 — رفع الملفات الضخمة مباشرة على الـ VPS**: أداة سطر أوامر (`datahub-import file.csv --country KW --dataset "اسم"`) تستخدم `COPY` الأصلي في Postgres — أسرع بـ 20–50 مرة من الرفع عبر المتصفح، ومناسبة لملفات 4 جيجا. ترفع الملف بـ scp ثم أمر واحد.

### إجابات مهمة
- **نعم**، بعد النشر تبقى تعدّل في Lovable ← Push إلى GitHub ← تشغّل أمر إعادة النشر (أو webhook تلقائي) وكل شيء يتحدّث.
- **لا**، قاعدة بيانات الـ VPS منفصلة تماماً: بيئة Lovable تبقى على قاعدتها (للتجربة)، والإنتاج على قاعدتك. البيانات لا تتزامن — تنقلها مرة واحدة بـ dump، وبعدها كل الرفع يتم على الـ VPS. الكود واحد، القاعدة تتغيّر بمتغيّر بيئة واحد.

## ترتيب التنفيذ
1. الدول الكاملة + دعم كل صيغ الملفات + تسريع الرفع
2. قاموس الأعمدة الديناميكي + شاشة المراجعة + عرض الأعمدة الفعلية
3. Data Filter (فلترة، Distinct، Merge/Split، حفظ/تصدير)
4. توضيح صلاحيات المفاتيح + توسيع الـ Public API (fields, filters, schema)
5. ملف DEPLOY.md بكل السكربتات

## تفاصيل تقنية
- جداول جديدة: `column_definitions`, `dataset_columns`, `saved_views`؛ فهرس GIN على `leads.extra`.
- قراءة XLSX عبر مكتبة في المتصفح؛ CSV/TXT عبر التدفق الحالي في `src/lib/csv.ts`.
- الفلترة تُبنى كـ SQL في دالة Postgres واحدة تخدم الداشبورد والـ Public API معاً.
